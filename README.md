# 字幕断句(Subtitle Segmenter)

基于 FastAPI + 原生 HTML/JavaScript 的字幕断句网页应用。用户粘贴带时间戳的词序列,可标记不可拆短语、按词间隙设置边界约束;系统在「每条最多两行、行宽与阅读速度限制」下,用全局动态规划选择分段,使 **镜头切点偏差 + 行长不均 + 不自然停顿** 的加权总代价最低。页面实时展示断句预览与逐段代价,调整权重或边界约束即时重算;无可行方案时定位首个冲突区间(或首个不可行边界)及具体原因并高亮。请求 `alternatives`(1～5,默认 1)大于 1 时,后端用 **K-best 动态规划** 返回总代价从低到高的备选方案,可在页面切换并突出与最优方案不同的断点。还可在预览中**锁定任意字幕段**:再次调整权重、边界约束或备选数量时,后端固定这些段的词范围与内部换行,只优化其余区间。此外可维护**术语表**(每项含规范写法与多个识别变体),对**当前选中的断句方案**做术语一致性审校:页面按字幕段高亮命中、汇总规范/变体次数并列出不一致项,支持审校结果 JSON 下载。还可按行粘贴**译文**,对当前选中的断句方案做**单调动态规划对齐**(1 段对 1～2 行或相邻 2 段对 1 行,代价为两侧去空白字符占比差,句末标点类别不一致 +0.15),页面按对齐组展示原文、译文与映射,并可**下载双语 SRT**。

## 启动

```bash
docker compose up --build
```

依赖安装与应用初始化均随容器启动自动完成,无需本地环境。启动后在浏览器打开 http://localhost:8000 即可使用(容器内监听 8000 端口,由 `docker-compose.yml` 映射到宿主机同名端口;如端口被占用,修改映射后访问对应宿主机端口)。

## 访问

- 网页界面: http://localhost:8000
- 断句 API:`POST http://localhost:8000/api/segment`
- 术语审校 API:`POST http://localhost:8000/api/terms/review`

## 边界约束

在「词序列 · 边界约束」面板中,点击两个词之间的间隙即可设置硬约束,再次点击循环切换,第三次点击清除:

| 标记 | 类型 | 含义 |
| --- | --- | --- |
| 红色竖线 | `must_break` | 必须断开:分段边界必须落在该间隙 |
| 绿色横线 | `no_break` | 禁止断开:间隙两侧的词必须落在同一段 |
| 紫色细线 | (不可设置) | 不可拆短语内部的间隙,不允许设置边界 |

约束随请求提交,在全局动态规划中作为硬条件生效。若约束导致无可行方案(例如必须断开后任一侧违反时长、行宽或阅读速度限制),响应返回**首个不可行边界**及具体原因,页面保留输入与标记,并高亮冲突边界与冲突词区间;调整约束或权重后即时重算。

## 锁定段(锁定后局部重算)

在「断句预览」中,每段右上角有 **🔒 锁定** 按钮。点击后该段的**词范围与内部换行位置**被固定(青色描边 + 🔒 标记,词序列预览中以青色标出锁定词范围与锁边界);再次点击(或冲突面板中的「解锁」)可解除。

- 锁定后调整**权重、边界约束、镜头切点或备选数量**,后端把锁定段的两个段边界转为 `must_break`、锁内词间隙转为 `no_break`,并以锁定换行作为该段唯一合法布局,**只优化锁定段之外的区间**;各自由区间与锁定段的组合仍在**同一张全局分段 DAG** 上做 K-best 动态规划 —— 跨区间组合按**全局总代价统一排序**,并按**完整断点序列去重**(全局总代价相同时按断点序列兜底判重),因此锁定不影响「K-best 全局最优」的语义,备选数量 1～5 的行为不变。
- 锁定段本身不再受权重变化影响(词范围、两行文本逐字保持);自由段的断点与换行照常优化。每段响应新增 `line_break`(段内换行处的词间隙下标,单行为 `null`)与 `locked` 标记(仅锁定段携带)。
- 下列情况锁定段**失效**,响应返回 `ok: false` 与**首个**冲突锁及具体原因,页面把问题段标红闪烁、在冲突面板中列出全部锁定段并保留锁定状态,可直接解锁或修正输入后自动重算:
  - **锁定段互相重叠**(首尾相接允许);
  - 词序列增删后锁定**词范围越界**、起点/终点落入不可拆短语内部;
  - 不可拆短语变化后,锁定的**内部换行落入短语内部**;
  - 锁定段(含锁定换行)在新参数下违反行宽、时长或阅读速度硬约束;
  - 锁定边界 / 锁内间隙与用户新设置的 `no_break` / `must_break` 约束冲突。
- 未传 `locks` 字段(或为空数组)时,请求与响应结构与旧版完全一致(仅每段多出恒存在的 `line_break` 字段)。

## 术语一致性审校

在左侧「术语表(一致性审校)」面板维护术语,每行一个,格式 `规范写法 = 变体1 / 变体2…`(分隔符支持 `=` 或 `:`,变体之间可用中英文逗号、分号、竖线、顿号、斜杠分隔);也接受 JSON 数组 `[{"canonical": "Wi-Fi", "variants": ["WiFi"]}]`。术语表或断句方案变化后自动对**当前选中的断句方案**(备选方案切换后即为该方案)重新审校,无需手动操作。

匹配与裁决规则:

1. 规范词与变体先做 **NFKC 归一 + 大小写归一(casefold)**,匹配文本中的词间空白不参与匹配 —— 因此术语可以**跨词**命中(如词序列 `人/工/智/能` 命中「人工智能」、`AI/model` 命中「AI model」),但匹配在每个字幕段内独立进行,**不跨字幕段**。
2. 每个字幕段用 **Aho-Corasick 自动机一次扫描**收集全部候选命中(允许嵌套与重叠),**不按术语逐个匹配**。
3. 同一位置存在嵌套或重叠候选时,用**区间动态规划**选择互不重叠的候选集合,依次按以下优先级取字典序最优的唯一解:**覆盖字符最多 → 非规范变体命中数最少 → 术语录入顺序稳定唯一**(早录入的术语优先;位次用互异二进位权编码,保证任何候选集合的比较结果唯一)。
4. 与规范词归一形一致的命中计为规范命中(绿色高亮),其余命中计为非规范变体命中(红色高亮)。

页面表现:右侧出现「术语一致性审校」面板,按字幕段在两行文本上**高亮命中**(绿=规范写法、红=非规范变体,悬停显示规范写法);顶部汇总字幕段数、命中总数、规范/变体次数,表格逐术语列出命中与各变体次数,并列出全部**不一致项**(变体写法 → 规范写法、所在段/行与上下文,点击可定位到对应字幕段)。点击「下载审校 JSON」可下载完整审校结果(含时间戳、术语表与逐段命中)。

术语表本身的问题返回 HTTP 422,页面提示**术语序号(从 1 开始)且保留输入**:

- 规范写法归一后为空:`detail = {"type": "empty_canonical", "term_index": <从 0 开始的术语下标>}`;
- 同一归一写法被两个不同术语声明(变体归属冲突,如两个术语的规范词大小写归一后相同,或某术语的变体等于另一术语的规范写法):`detail = {"type": "variant_conflict", "term_indices": [<下标…>], "surface": "<归一写法>"}`。同一术语内变体归一后与其规范词相同者按规范写法处理,不视为冲突;空白变体与术语内重复变体忽略。

## 译文对齐(双语 SRT)

在右侧「译文对齐」面板按行粘贴译文(每行一条,空行忽略),系统对**当前选中的断句方案**(备选方案切换后即为该方案)与译文行序列做**单调动态规划对齐**:两侧均按序消费、不交叉,且完整覆盖两侧。断句方案或译文任何变化都会自动重算,无需手动操作。

允许的组型(每组源段数 : 译文行数):

| 组型 | 含义 |
| --- | --- |
| `1:1` | 一个源段 对 一行译文 |
| `1:2` | 一个源段 对 相邻两行译文 |
| `2:1` | 相邻两个源段 对 一行译文 |

**每组代价** = 两侧长度占比差绝对值 + 句末标点惩罚:

- 占比 = 组内该侧**去空白字符数** ÷ 该侧全文去空白字符数;
- 组末**句末标点类别**不一致时 +0.15。类别按组内最后一项文本的最后一个非空白字符判定:句点(`.` `。` `｡` `．`)、疑问(`?` `？`)、感叹(`!` `！`)、省略(`…` `‥`)、其他(无标点或其余符号)。

总代价最小的完整覆盖即所求。**同分裁决**:把路径看作组型序列,从第一组起依次比较,首个不同组按 `1:1 → 1:2 → 2:1` 取优先 —— 即优先 1:1;其次源侧结束位置更早的组(1:2 的源侧结束位置早于 2:1)。实现上把每组代价改写为整数(0.15 = 3/20,通分后总代价 = 整数和 ÷ (20·S·T),S/T 为两侧全文去空白字符数)做后缀 DP,再按组型优先序贪心重建路径,同分判定精确、无浮点误差。

页面按对齐组展示:组型标记(1:1 绿 / 1:2 蓝 / 2:1 紫)、时间范围(首尾源段起止)、源段与译文行映射、合并后的原文与译文、占比差与句末标点是否一致、每组代价与总代价。

- **任一侧为空或无法完整覆盖**时,面板提示**首个未覆盖位置**(源段第 N 段或译文第 N 行)并保留全部输入:译文为空时首个未覆盖为源段第 1 段;无断句方案(词序列为空或断句冲突)时首个未覆盖为译文第 1 行;一侧项数超过另一侧两倍(每组至多 1:2 / 2:1,如 3 段源对 7 行译文)时无法完整覆盖,首个未覆盖位置为第 2×min(段数, 行数)+1 项。调整译文行数或断句方案后自动重算。
- **下载双语 SRT**:对齐成功后可下载 `bilingual.srt`,每个对齐组生成一条字幕,时间取该组首尾源段的起止范围,组内原文与译文各自合并为一行(原文行在前、译文行在后,多项以单空格连接),文件带 UTF-8 BOM。

## 配置

无需环境变量;所有参数在网页左侧面板调整(也可通过 API 的 `config` 字段传入):

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `max_chars_per_line` | 42 | 单行最大字符数(硬约束,每段最多 2 行) |
| `max_cps` | 20 | 最大阅读速度,字/秒(硬约束) |
| `min_duration` | 0.8 | 每段最短时长,秒(硬约束) |
| `max_duration` | 7.0 | 每段最长时长,秒(硬约束) |
| `pause_threshold` | 0.3 | 词间间隔小于该值视为不自然断点,秒 |
| `shot_dev_cap` | 0.5 | 镜头切点偏差归一化上限,秒 |
| `crossing_penalty` | 1.0 | 分段跨越一个镜头切点的惩罚 |
| `w_shot` | 1.0 | 权重:镜头切点偏差 |
| `w_imbalance` | 1.0 | 权重:行长不均 |
| `w_pause` | 1.0 | 权重:不自然停顿 |

## 输入格式

- **词序列**:每行 `开始 结束 文本`,时间支持 `HH:MM:SS.mmm` 或秒数;也接受 JSON 数组 `[{"text","start","end"}]`。
- **不可拆短语**:每行一个,词下标区间(如 `3-6`,含端点)或短语原文(自动匹配首个连续出现)。
- **边界约束**:在词序列预览中点击词间间隙设置(见上节);约束按词间隙下标解释,修改词序列后请核对位置。
- **镜头切点**:每行一个时间点。
- **术语表**(仅术语审校使用):每行 `规范写法 = 变体1 / 变体2…`,或 JSON 数组;对当前选中的断句方案生效,不影响断句计算。
- **译文**(仅译文对齐使用):每行一条译文,空行忽略;对当前选中的断句方案做对齐,不影响断句计算。

## API

`POST /api/segment`,请求体:

```json
{
  "words": [{"text": "我们", "start": 0.5, "end": 0.9}],
  "phrases": [[4, 5, 6]],
  "shots": [4.5, 8.0],
  "boundaries": [{"index": 7, "type": "must_break"}, {"index": 10, "type": "no_break"}],
  "locks": [{"word_range": [3, 7], "line_break": 5}],
  "alternatives": 3,
  "config": {"max_cps": 20, "w_shot": 1.0}
}
```

- `words`(必填):词序列,含 `text` / `start` / `end`(秒)。
- `phrases`(可选,默认 `[]`):不可拆短语的词下标区间(连续、含端点)。
- `shots`(可选,默认 `[]`):镜头切点时间(秒)。
- `boundaries`(可选,默认 `[]`):词间隙边界约束。`index = k` 表示词 `k-1` 与词 `k` 之间的间隙(`1 <= k <= len(words)-1`);`type` 为 `must_break`(必须断开)或 `no_break`(禁止断开)。同一间隙不得同时设置两种类型;间隙不得位于不可拆短语内部,否则返回 422。**不传该字段时行为与旧版完全一致。**
- `locks`(可选,默认 `[]`):锁定段数组,每项 `{"word_range": [a, b], "line_break": k}`:`word_range` 为含端点的词下标区间,`line_break` 为段内换行处的词间隙下标(`k` 在 `(a, b]` 内,即词 `k-1` 与词 `k` 之间换行),传 `null` 表示锁定为单行。重算时锁定段的词范围与两行文本逐字保持,只优化其余区间;跨区间的 K-best 组合仍按全局总代价排序、按完整断点序列去重。锁定段之间不得重叠(首尾相接允许);`a`/`b` 必须是词序列或不可拆短语的合法边界,`line_break` 不得落在短语内部。**不传或为空数组时请求/响应与旧版一致。**
- `alternatives`(可选,默认 `1`,取值 1～5):请求的备选方案数。全部硬约束(行宽、行数、阅读速度、时长、不可拆短语)、边界约束(`must_break` / `no_break`)与锁定段对所有方案一视同仁;后端在分段 DAG 上做 K-best 动态规划,按**分段边界序列判重**,返回总代价从低到高的互不重复方案(所有备选方案包含完全相同的锁定段)。不足 `alternatives` 个时返回实际数量(最少 1 个,即至少有一个可行方案时)。
- `config`(可选):见「配置」表,未传字段取默认值。

响应:

- 可行:`{"ok": true, "total_cost": ..., "segments": [...]}`;当且仅当 `alternatives > 1` 时额外含 `alternatives` 数组,第 0 项即顶层最优方案(`cost_delta` 为 0):
  ```json
  {"ok": true, "total_cost": 2.6667, "segments": [...],
   "alternatives": [
     {"segments": [...], "total_cost": 2.6667, "cost_delta": 0.0},
     {"segments": [...], "total_cost": 2.7, "cost_delta": 0.0333}
   ]}
  ```
  每项含 `segments`(结构与顶层 `segments` 相同)、`total_cost`(总代价)和 `cost_delta`(与最优方案的总代价之差,按未取整代价计算后四舍五入到 4 位小数,故可能与取整后两项之差相差 0.0001);顶层 `total_cost` / `segments` 始终代表最优方案,因此不传 `alternatives` 或传 1 时响应与旧版完全一致。每个 `segment` 字段:

  | 字段 | 说明 |
  | --- | --- |
  | `word_range` | `[首词下标, 末词下标]` |
  | `start` / `end` / `duration` / `cps` | 起止秒、时长、字符/秒 |
  | `lines` | 一行或两行文本(锁定段为锁定时的原文,逐字保持) |
  | `line_break` | 段内换行处的词间隙下标(单行为 `null`),可直接作为再次请求的 `locks[].line_break` |
  | `cost` | 各代价项与合计 |
  | `locked` | 仅当该段是请求中的锁定段时出现,值为 `true` |

- 不可行:`{"ok": false, "conflict": {...}}`(不含 `alternatives`),`conflict` 含冲突区间 `word_range` / `start` / `end` / `text` / `reasons`(具体违例,如「时长 0.30s 低于下限 0.8s」);若不可行由边界约束导致,另含 `boundary: {"index", "type"}`,即首个不可行边界。
- 锁定段冲突时,`conflict` 额外含 `"kind": "lock"` 与 `"lock": {"word_range": [a, b], "line_break": k}`(回显**首个**问题锁的请求值,可能越界),`reasons` 给出具体原因,典型如:
  - `锁定段(词 3–6)与已锁定段(词 0–3)重叠,请先解锁其中一段`
  - `锁定段词范围 [8, 12] 越界(合法范围 0–9),词序列已变化,请解锁后重新锁定`
  - `锁定段起点词 3 位于不可拆短语内部,不能作为段边界,请解锁后调整(短语已变化)`
  - `锁定段的内部换行词间隙 5(词 4 与词 5 之间)位于不可拆短语内部,不能换行,请解锁后调整`
  - `锁定为单行后长度 55 超过单行上限 42 字符` / `锁定的内部换行(词间隙 5)使行长 48 超过单行上限 42 字符`
  - `锁定段内部词间隙 2 被设置为必须断开,与锁定段词范围冲突`
  - `锁定段(词 2–6)固定了其边界(词 1 与词 2 之间必须断开), 但左侧区间(词 0–1)在当前参数下无可行分段; 请调整权重/约束或解锁该段`(锁本身合法,但锁定边界迫使相邻自由区间在新参数下不可行;此时同时回显 `boundary`)

### `POST /api/terms/review`(术语一致性审校)

对**当前选中的断句方案**执行术语一致性审校。请求体:

```json
{
  "words": [{"text": "咱们", "start": 0.5, "end": 0.9}],
  "segments": [{"word_range": [0, 3], "line_break": 2}],
  "terms": [
    {"canonical": "我们", "variants": ["咱们"]},
    {"canonical": "动态规划", "variants": ["DP"]}
  ]
}
```

- `words`:与 `/api/segment` 相同的词序列(含 `text` / `start` / `end`)。
- `segments`:当前选中方案的字幕段数组(即 `/api/segment` 响应中的段,备选方案则为所选 `alternatives[i].segments`)。每项只需 `word_range: [首词, 末词]`(含端点)与 `line_break`(段内换行处的词间隙下标,单行为 `null`)。各段必须按词序**连续、不重叠、完整覆盖** `words`,否则返回 422;`line_break` 必须在该段词间隙范围内。
- `terms`:术语表,每项 `{"canonical": "规范写法", "variants": ["变体1", "变体2"]}`,空数组时返回空审校结果。

成功响应(节选):

```json
{
  "ok": true,
  "segment_count": 1,
  "segments": [{
    "index": 0,
    "word_range": [0, 3],
    "line_break": 2,
    "text": "咱们 今天 用 DP",
    "hits": [
      {"start": 0, "end": 2, "term_index": 0, "kind": "variant",
       "text": "咱们", "canonical": "我们", "variant": "咱们"}
    ],
    "lines": [
      {"text": "咱们 今天", "hits": [{"start": 0, "end": 2, "...": "..."}]},
      {"text": "用 DP", "hits": []}
    ]
  }],
  "summary": {
    "terms": 2, "segments": 1, "hits": 2,
    "canonical_hits": 0, "variant_hits": 2,
    "by_term": [
      {"term_index": 0, "canonical": "我们", "hits": 1,
       "canonical_hits": 0, "variant_hits": 1,
       "variants": [{"variant": "咱们", "count": 1}]}
    ]
  },
  "inconsistencies": [
    {"term_index": 0, "canonical": "我们", "variant": "咱们",
     "text": "咱们", "segment_index": 0, "line": 1, "start": 0, "end": 2}
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `segments[].text` / `hits` | 段全文(词以单空格拼接)与选中的非重叠命中间隔;命中的 `start` / `end` 为段全文字符区间(跨词命中包含词间空格),`kind` 为 `canonical` / `variant`,`text` 为命中原样文本,`term_index` 为术语下标 |
| `segments[].lines[]` | 按 `line_break` 拆出的一/两行文本与行内命中(区间为该行内偏移;跨词术语落在行边界两侧时分别在两行中给出) |
| `summary` | 术语数、字幕段数、命中总数、规范命中数、变体命中数;`by_term` 逐术语汇总命中、规范/变体次数与各变体次数 |
| `inconsistencies[]` | 每个非规范变体命中一条:归属术语(`term_index` / `canonical` / `variant`)、所在段与行(`segment_index` / `line`,行号从 1 开始)、行内区间与上下文 |

错误响应(HTTP 422):术语表问题时 `detail` 为结构化对象 —— 空规范词 `{"type": "empty_canonical", "term_index": n}`,变体归属冲突 `{"type": "variant_conflict", "term_indices": [n, m], "surface": "..."}`;段不连续/越界等问题时 `detail` 为错误消息字符串。前端「下载审校 JSON」导出的文件在此响应基础上额外包含 `generated_at`(ISO 时间戳)与提交的 `terms` 术语表。

### `POST /api/align`(译文对齐)

对**当前选中的断句方案**与按行粘贴的译文执行单调动态规划对齐(组型 `1:1` / `1:2` / `2:1`,规则见「译文对齐」节)。请求体:

```json
{
  "words": [{"text": "我们", "start": 0.5, "end": 0.9}],
  "segments": [{"word_range": [0, 6], "line_break": null}],
  "translation": "第一行译文\n第二行译文"
}
```

- `words` / `segments`:与 `/api/terms/review` 相同(`segments` 为当前选中方案的段,`line_break` 可省略,对齐不使用);`segments` 为空数组表示当前无断句方案。
- `translation`:译文原文,按行拆分,各行去除首尾空白并忽略空行。

成功响应(HTTP 200):

```json
{
  "ok": true,
  "n_segments": 2, "n_lines": 3,
  "src_chars": 32, "tgt_chars": 90,
  "total_cost": 0.4597,
  "groups": [{
    "index": 0, "kind": "1:1",
    "src_segments": [0], "tgt_lines": [0],
    "src_text": "我们 今天 来看 一个 非常重要 的 例子",
    "tgt_text": "Today we look at a very important example.",
    "start": 0.5, "end": 3.3,
    "src_chars": 15, "tgt_chars": 35,
    "ratio_diff": 0.0799, "punct_mismatch": true, "cost": 0.2299
  }]
}
```

| 字段 | 说明 |
| --- | --- |
| `groups[].kind` | 组型 `1:1` / `1:2` / `2:1` |
| `groups[].src_segments` / `tgt_lines` | 组内源段下标 / 译文行下标(均从 0 开始) |
| `groups[].src_text` / `tgt_text` | 组内原文 / 译文(多项以单空格合并为一行,可直接用于 SRT) |
| `groups[].start` / `end` | 组时间范围:首源段开始、末源段结束(秒) |
| `groups[].src_chars` / `tgt_chars` | 组内两侧去空白字符数 |
| `groups[].ratio_diff` | 两侧占比差绝对值(四舍五入到 4 位) |
| `groups[].punct_mismatch` | 组末句末标点类别是否不一致 |
| `groups[].cost` | 组代价 = `ratio_diff` + (不一致时 0.15) |
| `total_cost` | 全部组代价之和(按未取整代价计算后四舍五入到 4 位) |

无法对齐时返回 HTTP 200 与 `{"ok": false, "n_segments", "n_lines", "error": {...}}`,`error.type`:

- `empty_source`:无断句方案(源侧为空);
- `empty_translation`:译文为空;
- `no_cover`:无法完整覆盖(一侧项数超过另一侧两倍)。

`error.first_uncovered = {"side": "source" | "translation", "index": k}` 给出首个未覆盖位置(0 起下标),`error.message` 为可直接展示的提示。断句方案不连续/越界等问题返回 HTTP 422,`detail` 为错误消息字符串。

## 备选方案(页面)

在「约束与权重」面板把**备选方案数量**设为大于 1 后,断句预览顶部出现方案切换条:`最优方案` 与 `方案 2…N`,非最优按钮标注相对代价增量(如 `+0.0333`)。切换后:

- 预览分段、逐段代价与总代价随所选方案更新;
- 词序列中用蓝色竖线标出当前方案断点,与最优方案不同的断点用**橙色**加粗竖线;最优方案有、当前方案没有的断点用蓝色空心圆标出(用户手动设置的必须断开 / 禁止断开标记不被覆盖);锁定段边界始终用青色竖线标出;
- 段首断点与最优方案不同的分段以橙色描边并标注「断点不同于最优」;
- 已锁定段在每个备选方案中保持同一段,以青色描边并标注「🔒 已锁定」;
- 只有一个可行方案时显示「只有一个可行方案,无更多备选」。
